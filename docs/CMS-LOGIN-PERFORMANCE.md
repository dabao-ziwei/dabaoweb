# 管理後台登入效能修正

## 範圍

本分支 `fix/cms-login-latency` 交付登入加速修改與本機驗收結果，正式 Edge 部署仍須另行核准；合併前端 PR 不會自動更新 Edge Function。
不修改資料表、RLS、管理員權限、密碼規則、登入期限、監測工具或網站文案版型。

## 原本的等待

- 輸入帳密後，前端依序請求 `login → session → state` 才拿到完整儀表板
- 這條路徑總共呼叫 9 次 Auth／資料服務，兩次登入節流也依序等待
- Edge 入口在任何請求前都先讀取並初始化約 15 MiB 圖片 WASM，連登入、健康檢查與公開讀取都會經過
- 原本可能先露出空白 workspace，再等待 state 回應

## 本機修改

- 登入成功回應一併帶回儀表板資料；前端只需一次 `login`，不重複查 session／state
- 帳號與 IP 的持久化節流仍為 5／20 次，只讓兩個獨立檢查並行，任一超限仍拒絕
- Auth 驗證通過後才讀取儀表板；建立 session 的最後一次 RPC 仍重新檢查管理員名單，撤銷權限時不回傳 token 或資料
- 只在已授權的上傳／遮蔽操作才延遲載入 JS／WASM，成功初始化後在該 isolate 重用，失敗可重試
- 非圖片讀取、登入、CORS 預檢與健康檢查不初始化圖片引擎；保留單一圖片工作限制及原圖驗證／遮蔽流程
- 資料備妥才顯示 workspace；等待時按鈕顯示「登入中...」、停用重送並標示 aria-busy
- 新前端也支援舊 Edge 回應（沒有 bundled state 時再讀一次 state）；原 Node／Cookie／CSRF 模式仍保留

## 對照測試

基準為 `984f6a1`。使用 Git 原始版本與修改版、相同隔離 Postgres／Auth 替身及瀏覽器，為每個 HTTP／資料服務呼叫注入固定 400 ms 延遲。

| 項目 | 原始版 | 修改版 |
| --- | --- | --- |
| 按下登入後前端請求 | 3 | 1 |
| Auth／資料服務呼叫 | 9 | 7（其中兩項並行） |
| 到資料完整顯示的單次本機計時 | 5.37 秒 | 3.33 秒 |

本次單次對照縮短約 38%，不是正式站統計，也不包含真正託管環境冷啟動。
正式帳密已更新，本輪沒有成功執行正式站的有效登入計時，也未重試或重設密碼。
不能將本機結果宣稱為正式站登入時間保證；正式改善幅度需在核准部署後由擁有者實測。

## 上線順序

1. 本機 Review 與人工核准
2. 再次 QA、提交與繁體中文 PR
3. 另經核准部署包含延遲圖片載入與 bundled state 的 Edge Function
4. 人工合併前端 PR，等待 GitHub Pages 部署
5. 以正式帳密驗收；不透過聊天室索取密碼

先部署 Edge 可向後相容既有前端；新版前端遇到舊 Edge 也可登入，但尚未取得完整的單請求改善。
